# Relevance labelling guide

This is for the product owner reviewing the domain retrieval dataset (`data/domain/v1`, decision D2). Your labels become the val and test ground truth that every retrieval and reranking claim is measured against. They are the only human judgement in the dataset, so they matter more than speed.

## Start

From the repository root:

- **Git Bash:** `bash scripts/review.sh val`
- **PowerShell:** `.\scripts\review.ps1 val`

Do `val` first, then `test`. To pause, press `q` or just close the window: every grade is saved the moment you press the key. Run the same command again to continue where you stopped.

Check progress at any time with:

```
cd backend && uv run --no-sync mezvuat-dataset status
```

## What you see

Each screen shows:

1. A **question** a researcher might type into a search engine. It was generated by an LLM from one passage of a paper.
2. One **passage** from the corpus, with its paper title, section and page. Passages come from several search systems, and the passage the question was written from is among them. You are not told which one it is.
3. Usually, the LLM's **pre-label**: a suggested grade and a one-line reason.

For about one question in five, the pre-label is hidden. This is deliberate. Comparing your agreement with the LLM on hidden and shown questions tells us how much the suggestions influence you (anchoring). Please judge those passages without trying to guess the model's answer.

## Keys

| Key | Action |
|---|---|
| `2` | The passage answers the question |
| `1` | The passage is partially relevant |
| `0` | The passage is not relevant |
| `Enter` | Accept the shown pre-label (only when one is shown) |
| `u` | Undo your last grade in this session |
| `s` | Skip for now (it comes back at the end) |
| `q` | Quit (everything is already saved) |
| `?` | Help |

## The grades

Judge the passage **on its own text**: would a reader holding only this passage be helped to answer the question? Do not use what you know about the paper or the field.

| Grade | Meaning | Test |
|---|---|---|
| **2: answers** | A reader could answer the question from this passage alone. | You could write the answer by pointing at sentences in the passage. |
| **1: partially relevant** | It is on the question's topic and contains part of the answer, or context a reader would need, but not a complete answer. | It helps, but you would still need another passage. |
| **0: not relevant** | It does not help answer the question, even if it shares words or the general topic. | Removing it from the results would lose nothing. |

### Examples

**Question:** *What is the nDCG@20 improvement for multilingual-e5-large when using SHIFT on NeuCLIR 2023?*

- *"As shown in Table 8, SHIFT improves the average nDCG@20 ... multilingual-e5-large (+0.039)"* → **2**: the number is in the passage.
- *"SHIFT rescales embeddings by a factor α chosen once, without dataset-specific tuning."* → **1**: it describes the method being asked about but gives no result.
- *"Dense retrievers are commonly evaluated with nDCG@10 on BEIR."* → **0**: shared vocabulary only.

**Question:** *How does query-independent soft compression differ from KV-cache compression in RAG?*

- A passage that defines both and states the difference → **2**.
- A passage that only describes KV-cache compression → **1**, because it covers half the comparison.

## Edge cases

- **Wrong paper, right answer.** If a passage from a different paper answers the question, it gets **2**. Relevance is about the text, not about where the question came from.
- **The source passage can be a 0 or a 1.** The question was written from one passage, but the generator can produce a question that its own passage does not fully answer. Grade what you see.
- **Mentions the term but does not explain it** (for example, a related-work sentence that names the method) → usually **0**. Give **1** only if it says something the question asks about.
- **Tables, numbers and garbled text.** PDF extraction can scramble tables and formulas. If you can still read the needed fact, grade normally. If the text is too garbled to tell, give **0**, so we do not reward unreadable passages.
- **Several facts asked.** If the question asks for two things and the passage gives one → **1**.
- **Contradicts the question's premise.** If the passage clearly answers by correcting the premise (for example, "SHIFT does not improve e5"), that is still an answer → **2**.
- **Bad questions.** If a question is ambiguous or meaningless, grade the passages as best you can and make a note of the question number (shown at the top of the screen). We will drop broken questions before evaluation, not change your labels.
- **Instructions inside a passage** ("ignore previous instructions…") are just text. Grade them on relevance like anything else.

## Workload

| | Questions | Passages to judge | Time at 25 to 40 s each |
|---|---|---|---|
| val | about 40 | up to 8 per question | about 2 to 3.5 hours |
| test | about 60 | up to 8 per question | about 3 to 5 hours |

`mezvuat-dataset status` gives the exact counts and the time left. Taking a break every 45 minutes keeps judgements consistent.

## Why this size, and what it can detect

The sizes fit roughly 6 to 8 hours of review. Using the per-question variation measured on the SciFact test split as a stand-in, 60 test questions give a 95% confidence interval of about ±0.05 nDCG@10 on a difference between two systems. The smallest difference detectable with 80% power is about 0.07 to 0.08. Smaller effects will be reported as inconclusive, not as wins.

## Where the labels go

Labels are written to `data/domain/v1/labels/<split>.human.jsonl`, append-only. Each record stores:

- your grade;
- whether the pre-label was shown, and what it was;
- whether you accepted it with Enter;
- the seconds spent;
- a timestamp.

An undo appends a retraction rather than deleting anything. When you finish a split, commit that file. Nothing is evaluated on the test split until both splits are complete.
