# M7 verification report: frontend

Executed 2026-11-15 on the dev machine (Windows 11, Node 24.13, npm 11.6, Python 3.13), branch `phase-2`. Commands ran from Git Bash after `. scripts/dev-env.sh`. That script keeps the npm and Playwright caches on X: and turns off Next.js telemetry.

**The smoke test runs against a MOCKED backend, not the real Mezvuat API.** Docker Desktop was stopped, so Postgres, Qdrant and the API could not run. Every API response in the Playwright tests comes from typed fixtures (`frontend/tests/fixtures.mts`), served in two ways:
- through Playwright's `page.route`, at the browser's network layer;
- by a stand-in HTTP server (`frontend/tests/stub-server.mts`) behind the real Next.js proxy.

## What was built

**Frontend (`frontend/`):**
- Next.js 16.4.6, React 19.3 and TypeScript 5.9. The versions, and why they were chosen, are in the ADR-0002 amendment of 2026-11-15.
- **Pages:**
  - workspaces;
  - a workspace's documents, with upload and URL ingest;
  - the research chat;
  - a document view that opens at a version, page and span given in `?version&page&start&end`.
- **Components:**
  - **Version table:** labels, ordinals and the latest flag; dates by kind, at their stated precision, with source and confidence. `ingested_at` is in its own column, labelled "not a document date". Also ingestion status (polled while a version is still ingesting), errors, licence and public-corpus verification.
  - **Workflow progress:** a chip for each workflow node, driven by the SSE `node` events. The streamed answer text appears as it arrives, along with any reset or replacement notices.
  - **Sanitized Markdown answer:** `[E#]` citation buttons, with injection-suspect styling.
  - **Evidence viewer:**
    - document, version, cited page and dates by kind;
    - an injection-suspect warning;
    - the quoted spans;
    - the page text with the exact span highlighted, and previous and next page buttons.
  - **Panels:** limitations (with the answer's flags), conflicts and claim verdicts.
  - **Badges:** backend, provider, model, fallback and data policy.
  - **Feedback:** on the whole answer, with an optional comment, and on each claim.
- **API types** are generated by `openapi-typescript` from `frontend/openapi.json`. The SSE payloads, which OpenAPI does not describe, are typed in `src/lib/events.ts` on top of the generated `FinalAnswer`.
- **Proxy:** a same-origin `/api/v1` proxy adds `MEZVUAT_API_KEY` on the server.

**Backend changes needed by the UI (commit `47e0348`):**
- `RunOut.answer` is now typed as `FinalAnswer`, and `summary` as `RunSummaryOut`. The generated types therefore include citations, dates and `injection_suspect`.
- `GET /api/v1/workspaces/{ws}/documents/{doc}/versions/{ver}/text?page=|at=` returns one page of the normalized text with its absolute `start` and `end`. The viewer highlights `text[char_start - start : char_end - start]`, so the span is never re-matched in the browser.
- `POST /api/v1/workspaces/{ws}/runs/{run}/feedback` takes `{rating: up|down, claim_id?, comment?}` and stores it in a new `run_feedback` table (migration `0003`). **Forwarding feedback to Langfuse is not done; it is part of M6.**
- `scripts/export_openapi.py` writes `frontend/openapi.json`; `--check` fails if the file is out of date.

**Test 1** (citation click, `page.route`):
- After the question is asked, every node chip reaches `done` from the SSE events, and `reformulate` is `skipped`.
- Clicking `[E1]` shows "Temporal RAG Paper", cited page 2, "Page 2 of 3", and a `<mark>` whose text equals the quote exactly. The text request is `?page=2`, and no injection warning is shown.
- Clicking `[E2]` shows page 1, the injection-suspect quote highlighted, and the warning.
- "Open in the document view" goes to `/documents/doc_rag?version=ver_2&page=1&start=…&end=…`, which shows the same page and highlighted span.
- The badges show backend `direct`, provider `groq`, "no fallback" and "cloud allowed (public corpus)".
- The limitations and conflicts panels render.
- "Helpful" posts `{rating: "up", comment: null}`.
- No request went unmocked.

**Test 3** (through the real proxy):
- The stub API streams one SSE event every 100 ms, and the streamed answer text appears before the final answer replaces it.
- The citation opens page 2 with the span highlighted.
- The stub received every request with `Authorization: Bearer smoke-test-key`. That is a fake value, set only in `playwright.config.ts`. It never appears in the page.

**Test 2** (document list):
- v1 and v2 are shown, with v2 marked latest.
- "Published 2024-03-05" is shown. A month-precision revised date is shown as "2024-06", never as "2024-06-01".
- The document is marked "verified public corpus".
- A failed version shows its error message and "unknown" dates.
- URL ingest posts `{url}` and shows "Accepted".

**Sanitized Markdown** (part of test 1). The answer fixture contains:
- a `<script>` block;
- inline `<img onerror>` and `<b>`;
- a Markdown image;
- a `javascript:` link.

None of them reaches the DOM: no `script`, `img` or `b` elements, no `javascript:` href, and `window.__pwned` stays undefined. A normal link shows its full URL, as ADR-0009 §5 requires.

## Not verified

- **The UI against the real API.** No end-to-end run used Postgres, Qdrant, the worker and a real research run. The fixtures follow the generated OpenAPI types, and `tsc` checks them. The SSE event shapes are checked only against `backend/src/mezvuat/api/routers/runs.py` and its tests, not against a live stream.
- **The frontend in compose.** The compose file validates, but the image was never built and the stack was never started, because Docker Desktop was stopped and was not to be started. The `node:24.13-alpine` tag exists on Docker Hub (checked through the Hub API). The standalone build and its healthcheck have not been run in a container.
- **The new backend endpoints against Postgres.** The version-text endpoint and SQL feedback storage have integration tests (`tests/integration/test_runs_persistence.py`), but those were skipped because no database was running. The unit tests cover the window logic and the feedback API with an in-memory store.
- **Uploads through the proxy.** The upload form is built, but no test covers a multipart upload through the proxy.
- **The GitHub Actions run.**
- **Browsers other than Chromium**, and any accessibility audit beyond what the tests' role-based selectors exercise.

## Known limitations

- **Conflicts panel.** It lists `contradicted` claims only. Nothing produces that status until the NLI verifier exists (M5), and the panel says so.
- **Fallback badge.** It reads `summary.fallback`, or calls on more than one backend. The backend never reports either before M8, so the badge says "no fallback".
- **Chat history.** It lives in page state only. Reloading the research page empties it, though the runs remain stored and can be fetched with `GET /runs/{id}`.
- **ESLint and TypeScript versions.** ESLint stays on 9.x and TypeScript on 5.9 because of peer ranges in the Next ESLint plugins and in openapi-typescript (see the ADR-0002 amendment).
